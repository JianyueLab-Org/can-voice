机队镜像补上 ALSA：一个永远不碰声卡的容器，为什么要链接 alsa

PR 的镜像 job 报 `alsa-sys` 找不到 alsa —— 正是开这个 PR 要验的那件事，本机没有
docker 验不了。

`can-voice-client` **无条件**依赖 cpal（音频设备 I/O），所以 `alsa-sys` 的
build script 要有 alsa 的 pkg-config。而机队**运行时一个设备都不开** ——
`station.rs` 给的 Config 里写着 `audio_devices: false`，音频是 TTS 合成出来的
PCM 直接 push 进去的。

所以这两行纯粹是为了让链接过得去，不是这个容器真的需要声卡。注释里写明白了，
否则下一个人看到一个没有声卡的容器装 ALSA 只会以为是抄错了。

runtime 那层也要 `libasound2`：cpal 动态链接 libasound.so.2，哪怕一个设备都不开，
缺了它进程起不来。

想去掉的话得把 cpal 放进 `can-voice-client` 的一个 feature 后面 —— 那是四个桌面端
一起动的改动，不值得为一个 Dockerfile 里的两行做。
