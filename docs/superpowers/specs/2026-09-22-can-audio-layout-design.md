# 界面布局设计：四个桌面端搬回 can-audio 的排布

日期：2026-09-22
状态：待评审
范围：前端布局、窗口几何常量、xpc / msfs 的原生菜单。实施计划另写。

---

## 1. 为什么

四个 Tauri 桌面端是 can-audio 四个 PyQt6 客户端的替代品，**换的单位是"人换客户端"**
（README「怎么从 Mumble 切过来」）。切换日那天，管制员打开的是一个他没见过的窗口，
而他手上正有飞机。

管制端已经基本是 can-audio 的移植：232px 卡片栈、同一套
`#436384 / #28a745 / #c7861d / #dc3545`、同样的精简模式、同样的在线频率条。
另外三个端不是——通播端从两栏分割变成了三栏加折叠块，两个飞行员端丢了菜单栏和
四张卡片的排布。这次把四个端的**排布**对齐到 can-audio，把已经收敛的那一个补齐。

**功能一个不删。** can-voice 有 can-audio 没有的东西——健康统计、更新横幅、服务端
公告条、TX 配额告警、交叉耦合被拒告警、浅色主题、座舱读数、他机表。它们全部保留，
各自落在 can-audio 排布里最近的那个位置，§4–§6 逐个点名。

## 2. 决策摘要

| 决策 | 结论 | 理由 |
|---|---|---|
| 范围 | 四个端全做 | 只做一个端等于让另外三个端在切换日继续陌生 |
| can-voice 独有的界面 | 全留，塞进 can-audio 的排布 | 见 §1 |
| 共用件怎么共用 | 逐字节复制，扩测试防漂移 | 仓库现有约定；见 §3 |
| xpc / msfs 菜单栏 | Tauri 原生菜单 | can-audio 是 `QMenuBar`，HTML 菜单条既不像也不是 |
| 调色板 | `style.css` 里的 CSS 自定义属性 | 对应 can-audio 逐字节相同的 `theme.py` |
| 轮询与 Rust 命令面 | 不动 | 这次是布局，不是重写 |

不做：抽 npm workspace（要加根 `package.json`、共享 lockfile、四个端的构建步骤，
并替掉现有的逐字节相同断言），以及把这套外壳推进
`@jianyuelab-org/can-ui`（那是面向 Web 的包，而这套观感来自 TrackAudio 且只有暗色）。

## 3. 共用外壳与调色板

**调色板收到一处。** 现在这些颜色是散在组件里的十六进制字面量
（`apps/controller/src/components/RadioRow.vue:42-45`、`App.vue:344`、`App.vue:502`），
而 can-audio 只有一个 `theme.py`，且四个客户端逐字节相同。改为在
`apps/<app>/src/style.css` 里声明 CSS 自定义属性——那个文件本来就四份逐字节相同，
是 `theme.py` 的天然对应物：

```
--can-off #436384    --can-on #28a745      --can-active #c7861d
--can-muted #dc3545  --can-theme #5eb1bf   --can-idle #8b90a4
--can-surface #252839  --can-window #2c2f45
```

语义状态色在明暗两套主题下相同，浅色主题其余部分维持现有的 Tailwind 处理。
`style.css:46-73` 手工维护的那批暗色覆盖不动——换掉它们是另一件事。

**三个组件确实是共用的**，各自一份逐字节相同的副本：

- `StateToggle.vue`——手绘三态开关（`controller/gui.py:202-238`）。一个带尺寸属性的
  组件同时覆盖管制端的 RX / TX（52×26）、XC（36×22）、静音（46×22），以及
  xpc / msfs 的 TX / RX 色块（46×26）——在 can-audio 那边这是同一个控件。
- `Panel.vue`——带标题的卡片（`Card(HeaderCardWidget)`，`xpc/gui.py:111-125`）：
  标题条加内容插槽。两个飞行员端各四个。通播端**不**用它——can-audio 的通播右栏是
  裸控件配 `StrongBodyLabel` 小标题，不是卡片。
- `StatusBar.vue`——底栏：PTT 圆点、`PTT` 文字、占满剩余宽度的状态文案、值守文案
  （`controller/gui.py:650-668`）。xpc / msfs 的 `QStatusBar` 是同一条栏少几格。

只有一个端用到的留在本地：管制端居中的 `LoginCard`、在线频率的 `Pill`，以及替掉
can-audio `InfoBar.warning` 的右上角提示（4 秒自动消失）。

**防漂移。** `crates/can-voice-i18n/tests/dictionaries.rs:410` 现在只断言四份
`common.*.json` 逐字节相同。把这条断言扩成一张清单，覆盖现有共用文件和上面三个新
组件——改了一份而没改其余三份，CI 失败。这是「复制」这条路安全而不只是合乎习惯的
前提。

## 4. 管制端

**登录独立成页。** can-audio 是两页 `QStackedWidget`，can-voice 把凭据塞在页头里
（`apps/controller/src/App.vue:351-363`）。新增 `LoginCard.vue`：固定 340px 宽、
`rounded-lg`、居中应用名、用户名（`用户名（CAN 号）`）、密码（回车即连接）、
主按钮「连接」，下方一行状态文案，卡片外再一行版本号——即
`controller/gui.py:470-524`。连接错误进那行状态文案并着色，这是 can-audio 的位置。
`UpdateBanner` 留在卡片上方：没连上正是更新该发生的时刻。服务端公告不适用于这一页，
它只在连上之后才来。

**顶栏用 can-audio 的顺序**（`controller/gui.py:536-583`）：指示灯 → `已连接`/`已断开`
→ 会话文案 → 撑开 → 置顶 → 精简 → 设置 → 断开。`WindowToggles.vue` 本身就是
can-audio 的置顶/精简/设置三连，所以改动主要是把「断开」挪到最右、补上会话文案。
`App.vue:340` 的 `<h1>` 标题去掉——can-audio 主页面没有标题，标题在窗口装饰和登录
卡片上。

**添加频率栏**改成 can-audio 的比例：频率输入伸缩 1（最小 120 / 最大 200）、
呼号伸缩 2（最小 160 / 最大 340）、「添加频率」最小宽 112、尾部撑开
（`controller/gui.py:586-617`）。这里有一个要点名的后果：那一行现在还挂着**内联
`SettingsPanel`** 的开关（`App.vue:447-449`），而 can-audio 没有这个东西——它把音频、
PTT、日志都放进设置**对话框**。所以 `SettingsPanel.vue` 的三块并入
`SettingsDialog.vue`，设置从两个入口变成一个。功能没少（端点、故障排查照旧，只是
多了音频 / PTT / 日志作为同级），但这是**去掉一个重复入口**，不是单纯搬家。

**电台卡片**已经很接近，四处差异：高度和宽度一起固定（232×116，现在只有
`w-[232px]`）；频率用等宽 17px demibold，选中时前缀 `▸ `；增益滑杆按 can-audio 读
0–100，在组件内换算成桥接层的 0–2；最后通话那行用 can-audio 的措辞，空闲态
`最后通话: --`。

**在线频率条**压成一行——文案 `在线频率` 之后直接排药丸按钮，高 24px，只显示呼号，
已加入的**置灰而不隐藏**（`controller/gui.py:636-647`）。现在是标题另起一行、按钮同时
显示呼号和频率。

**底栏**变成圆点 + `PTT` + 占满剩余宽度的状态文案 + 值守文案（值守时为绿）。屏幕上
那个 PTT 保持真正的按住发话按钮，而不是 can-audio 的纯指示灯——Wayland 上它是唯一
能用的 PTT。健康统计守住右格。公告条、交叉耦合被拒、TX 配额三条横幅留在添加栏和
卡片栈之间，也就是它们现在的位置；校验错误改走右上角 4 秒提示。

**精简与几何。** 精简隐藏添加栏、在线条、底栏、空栈提示、连接文案、会话文案，以及
设置和断开；边距收到 `p-1.5` / gap 1；置顶和精简变成 30×26 纯图标。Rust 侧
`apps/controller/src-tauri/src/lib.rs:800,803` 的 `COMPACT_MIN` / `COMPACT_SIZE` 改成
248×186，`tauri.conf.json` 的最小尺寸改成 620×480。

## 5. 通播端

三栏工作区改成 can-audio 的**两栏加可拖分割条**，默认 260 / 其余
（`atis/gui.py:329,460-464`）。中间那栏得有去处，而 can-audio 已经给了答案：它的席位
编辑器是**模态**（`StationDialog`，`atis/gui.py:88-237`），不是内联栏。所以
`StationEditor.vue` 变成对话框，由「编辑」打开；`PresetEditor.vue` 同样变成对话框，
即 can-audio 的 `PresetDialog`（`atis/gui.py:1266-1330`），从右栏「编辑预设」进去。

**顶栏**取 can-audio 的形状：`账号:` + 用户名（110px）+ 密码（160px）→ 撑开 →
检查更新 → 设置（`atis/gui.py:301-327`）。can-voice 的配置档下拉和它的新建 / 重命名 /
删除在 can-audio 没有对应物，留在这一行左端。置顶和精简**移出**顶栏，进左栏的标题行
——can-audio 刻意放在那里，为的是精简模式下它们还在。

**左栏**（`atis/gui.py:333-403`）：标题 `通播席位` + 撑开 + 置顶 + 精简 → 席位列表 →
一块固定高度的按钮区：一行新建 / 编辑 / 删除，然后竖排 `从网络更新配置`、
`取在线席位`、`导入 vATIS 配置…`。后三个就是现在 `Import` 折叠块里的动作，所以消失的
是折叠块而不是动作。列表行改用 can-audio 的单行摘要形式——`● ZSPD  J  09004MPS  Q1013`
（`atis/script.py:81-105`），替掉现在的圆点加字母按钮。

另外两个折叠块在 can-audio 的左栏没有位置，而它把这些内容放进设置对话框
（`atis/settings.py:176-291` 就带着刷新间隔和等级）：所以 **Airing 并入
`SettingsDialog`**，`LogPanel` 一起，和管制端同一个合并。

**右栏**（`atis/gui.py:406-460`）自上而下：预设行（`预设:` + 下拉 + 编辑预设）→
字母行（`情报字母: J` + 推进字母 + 刷新天气）→ METAR 块，等宽换行，保持现在的可编辑
而不是 can-audio 的只读文案 → `文字通播` 只读框，固定 90px → `语音稿` 只读框，占满
剩余高度，装 can-voice 产出的中英两份（can-audio 只有一份）→ 播出行（`开始播出`
主按钮 + 状态文案）。未知变量告警和 `wire` 转储留在那一行下面。

**几何。** 最小尺寸改成 900×600（`apps/atis/src-tauri/tauri.conf.json`，现在是最小
720×480）。精简隐藏顶栏、席位按钮区和整个右栏，`apps/atis/src-tauri/src/lib.rs:1098,1101`
的 `COMPACT_MIN` / `COMPACT_SIZE` 改成 300×220 / 300×320；退出精简恢复 260px 的分割，
和 can-audio 一样。分割条宽度只活在会话里，不持久化——can-audio 也不持久化。

## 6. 两个飞行员端

这两个端在两边的代码里都是同一套布局（can-audio 的差异只在模拟器后端），所以一份
设计，msfs 作为 xpc 的差量落地。

**原生菜单**（`xpc/gui.py:202-228`）：文件 → 飞行计划…、设置…、─、退出；
帮助 → 打开日志目录、检查更新、关于。这一条就是 `PilotPanel.vue`（381 / 399 行）解体
的原因：它的**飞行计划**页变成 can-audio 的 `FlightPlanDialog`，从菜单进；它的
**本机**页变成设置对话框里的分页，设置对话框取 can-audio 的枢轴形式，音频 / 网络 /
他机（`xpc/gui.py:1077-1110`）。提示音开关和范围放到「他机」和他机设置一起。菜单项
派发到已经存在的 Rust 命令。

**四张带标题的 `Panel`**，按 can-audio 的排布（`xpc/gui.py:185-200`）：

- **连接**，整宽。网格：呼号 · CID · 密码 · 机型 · 连接（最小宽 110），然后三行状态
  文案——模拟器、FSD、语音，也就是现在页头那几个 pill 的去处。再是 `观察员` 加换行
  提示、`记住密码` 加提示。can-voice 多出来的 follow 和真实姓名留在网格里；独立的
  会话区并进来，连接按钮翻成断开，Ident 在旁边。
- **消息**（伸缩 3）和**附近管制**（伸缩 1）并排。消息是 `ChatLog` 加从底栏提上来的
  发送行（收件人最大 240 + 正文 + 发送）；附近管制是 `ControllerList`，双击发消息，
  下面一行换行提示。
- **无线电**，最下，一行：TX / RX 色块 → COM1 等宽 15 粗 → 仅观察员可见的手动频率
  （否则隐藏）→ 频道文案 → 撑开 → 他机计数 → 席位 → IDENT → PTT 按钮。

有两处 can-voice 的东西在 can-audio 没有位置。**座舱读数**剩下的格子（应答机、高度、
地速、航向、气压差）并入无线电那一行——can-audio 的无线电卡片本来**就是**模拟器状态
行，装着 COM1、频道、他机计数和席位，它们属于那里。**他机表**变成中间一行的第三张
卡片，伸缩 1，于是中间是 消息 3 ‖ 附近管制 1 ‖ 他机 1。xpc 的插件 pill 和它那两条
横幅（版本不符、没听到）留在卡片上方当横幅。

底部放一条 `StatusBar`，显示 `就绪` 和瞬时状态。几何改成 980×660；can-audio **不设**
最小尺寸，但这里保留 900×600——没有它三张卡片那一行会塌——这是**刻意的偏离**，不是
漏了。can-audio 这两个客户端根本没有精简模式；can-voice 的保留，精简时只留消息卡片，
也就是它现在的行为。

## 7. 文案与 i18n

每个新标签都要在 `apps/<app>/src/locales/app.{zh,en}.json` 里有中英一对。
`crates/can-voice-i18n/tests/dictionaries.rs` 查键位对齐和占位符，并**禁止 UI 代码里
出现硬编码中文**（`:608-623`）——所以 can-audio 自己那四处 i18n 漏网要按键搬，不是
照抄：通播端 `atis/gui.py:373` 的 `'新建' / '编辑' / '删除'`，以及它那两条长中文提示。

can-audio 已有的键名能用就沿用（`main.pin`、`main.compact`、`radio.mute`、
`online.title`、`duty.on`），让两边代码互相 grep 得到。

## 8. 验证
