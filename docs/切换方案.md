# 从 Mumble 换成 can-voice

**已经拍板：一并替换，没有共存期。** 这份文件原先是一份分阶段的方案，
五处标着「待定」等人决定；那些都不作数了，方案就是下面这一条路。

---

## 一、两件决定了"怎么换"的事实

### 1. 老客户端改不动地址

`can-audio/CLAUDE.md` 记着：Mumble 的主机名**写死在**
`client/radio.py`、`xplane_client/radio.py`、`controller/gui.py`、
`atis/gui.py`、`server/ATIS/mumble.py` 里，只有 `xpc/settings.py` 和
`msfs/settings.py` 把它当成一个可改的默认值。

所以**没有"改一行数据库就把所有人挪过去"这条路**。一个成员要用上 can-voice，
唯一的办法是**装一个新客户端**。换的单位是"人换客户端"，不是"服务器换地址"。

### 2. 两套不能跑在同一台机器的同一个端口上

Murmur 同时占 **TCP 64738 和 UDP 64738**，而 can-voice 的 QUIC 要
**UDP 64738**。同一台机器上第二个绑不上。

**在一并替换这条路上，这件事从障碍变成了帮手**：can-voice 直接接管原来那个
地址和端口，Murmur 停掉。于是老客户端连过去**握手就失败**——它拿 Mumble 的
TLS 去敲一个 QUIC 端口，什么也谈不拢。

这正是想要的结果。分阶段方案里最担心的故障是"掉队的人待在一个正常但空无
一人的频率里"——他看不出任何异常，而没有人听得见他。**连不上是会被报告的，
一个人的房间不会。**

---

## 二、为什么不留共存期

两套同时在线时，**同一个频率会分裂成两个互不相通的房间**：一半人在 Mumble、
一半人在 can-voice，双方都以为自己在守听，而管制员叫不到其中一半。

**这比"语音完全没有"糟得多**——完全没有语音时所有人都知道要改用文字，而分裂时
没有人知道自己少听见了谁。

共存期唯一能买到的是"边跑边测"，而它的代价正是这个分裂。一并替换把测试挪到
换之前（测试者之间自己连，不对外宣布），把风险压缩成一个明确的时刻。

---

## 三、顺序

### 换之前

- [x] can-api 的 `server` 表支持 `voice` 类别
- [x] can-voice 服务端能用 compose 部署
- [x] 四个客户端打包出来（Windows + Linux）
- [ ] **服务端通播出声**——见下面「四」，这是唯一还缺的功能
- [ ] `voice-keygen` 生成密钥对，两半分别进 can-api 和语音服务端
- [ ] 部署语音服务端（域名 / 证书 / 放行 UDP，见 `server/README.md`）
- [ ] 测试者之间验一轮：两个管制端互相听得见、跨运营商的抖动、通播、
      飞行员端、十人以上同频。**不对外宣布"可以用了"**，否则就退回共存期了

### 换的那天

1. 提前通知，窗口至少覆盖一个完整的活动周期——每个成员都要下载装一个新客户端，
   而大多数人一周只上线一两次
2. 停 Murmur 容器、停 Ice 认证器（`can-audio/server/login.py`）、停
   `server/ATIS/` 的 Mumble 机队
3. can-voice 起在同一个地址和端口上
4. `server` 表把 `audio` 那一行 `active` 置否，`voice` 那一行置是

**第 2 步内部的顺序不能反。** Ice 认证器是 Murmur 唯一的认证来源，Murmur 还在
跑的时候先停认证器，所有人会以为是自己的密码错了。

### 换之后

回滚要能在几分钟内做到，所以下面这些**停掉但不删**，留够至少一个活动周期：

- Murmur 容器（`docker compose start` 就回来）
- Ice 认证器
- `server` 表里 `audio` 那一行（置否而不是删掉）

**回滚不需要通知每个人**——老客户端本来就没被挪走，Murmur 一回来它们自己就
连上了。这是"老客户端改不动地址"这件事唯一的好处。

过了那个窗口再拆：`fix_acl.py`、`serverconf.py` 里只为 Murmur 存在的部分，
`server` 表里 `audio` 那一行，can-audio 仓库归档。

---

## 四、唯一还缺的功能：服务端通播出声

`can-audio/server/ATIS/mumble.py` 是一队**服务端的机器人**：用 edge-tts 把稿子
念成音频，再以 pymumble 连进 Mumble 的频率播出去。

**can-voice 这边没有对应的东西。** `atis-for-can` 只做稿子——它挂 FSD 席位、
把文字发出去，声音不归它管。所以照现在的状态一并替换，全网的通播会**哑掉**，
而不是听起来不一样。

这是换之前必须补的一件，不是换之后再说的一件：通播是飞行员在联系管制之前
唯一的信息来源。

## 五、这份文件没有覆盖的

- **CRC**：不在维护范围内。
- **macOS 客户端**：暂时不做。
- **网络可达性**：UDP 通不通不在这个项目的考虑范围内，P1 探针已经删掉，
  P2 Task 12（stream 回退）定为不做。如果换的那天发现大量人连不上 UDP，
  那是回滚的理由，而不是一个可以当场处理的问题。
- **语音质量的主观评价**：没有基线，也没打算建。
